# آزمون پذیرش نسخهٔ نامزد تحویل

آزمون پذیرش هرگز روی پایگاه اصلی اجرا نمی‌شود. نام پایگاه آزمایشی باید شامل `_acceptance_` باشد؛ ابزارها در غیر این صورت متوقف می‌شوند.

## معیارهای پذیرش

- رکورد فاقد `properties.name` نادیده گرفته شود.
- ترجمهٔ موجود بدون برچسب ویرایش حفظ شود.
- نام جدیدِ موجود در حافظهٔ تأییدشده ثبت شود.
- نام دارای برچسب ویرایش دوباره ترجمه و برچسب آن پاک شود.
- تغییر نام یک عارضه با هویت ثابت از حافظهٔ هویت‌مند بازیابی شود.
- نتیجهٔ مدل برای نام ناشناخته فقط در پیش‌نویس بماند.
- فراخوانی دستیِ ثبت انبوه با پاسخ حفاظتی متوقف شود.
- تمام تغییرات قطعی در تاریخچه قابل مشاهده و بازگردانی باشند.
- شمار رکوردها و داده‌های غیرترجمه‌ای پایگاه اصلی تغییر نکند.

## اجرای آزمون

راه‌انداز زیر از پایگاه اصلی یک کپی موقت می‌سازد، آزمون شش‌حالته را اجرا می‌کند، ثابت‌ماندن پایگاه اصلی را کنترل می‌کند و پایگاه موقت را حذف می‌کند:

```powershell
pwsh -File scripts\run_release_acceptance.ps1
```

گزارش در پوشهٔ `outputs/acceptance` ساخته می‌شود و باید مقدار `passed` برابر با `true` داشته باشد. برای بررسی جداگانهٔ چرخهٔ هویت نیز می‌توان پایگاه پذیرش مستقلی ساخت و این فرمان را با نشانی همان پایگاه اجرا کرد:

```powershell
node --env-file-if-exists=.env --env-file-if-exists=.env.local scripts\run_identity_cycle_acceptance.mjs --output work\model-evaluations\identity-cycle-acceptance-rc1.json
```

پیش از فعال‌سازی در محیط اصلی، یک نسخهٔ پشتیبان تازه تهیه شود.

## فعال‌سازی محدود

پس از تأیید گزارش پذیرش، فقط این مقدار تغییر می‌کند:

```dotenv
TRANSLATION_AUTO_APPLY=true
```

مقدار `TRANSLATION_ALLOW_API_APPLY` باید همچنان `false` باقی بماند. زمان‌بند فقط منابع قطعی را ثبت می‌کند و برای ثبت نتیجهٔ مدل مجوز ندارد.
