# آزمایشگاه ترجمهٔ نام‌های نقشه

## اجرای یکپارچه با داکر

پس از تنظیم مقادیر محلی در فایل‌های محیطی، پایگاه داده، سرویس پشتیبان و رابط کاربری با یک فرمان اجرا می‌شوند:

```powershell
docker compose up -d --build
```

نشانی رابط کاربری:

```text
http://127.0.0.1:3005/
```

نشانی سلامت سرویس پشتیبان:

```text
http://127.0.0.1:3006/health
```

برای مشاهدهٔ وضعیت سرویس‌ها از فرمان زیر استفاده شود:

```powershell
docker compose ps
```

توقف سرویس‌ها بدون حذف داده‌ها انجام می‌شود:

```powershell
docker compose stop
```

این پروژه فایل پشتیبان کارفرما را بررسی می‌کند، رکوردهای قابل ترجمه را روی نقشه نشان می‌دهد و بدون تغییر فایل اصلی، یک نسخهٔ کامل جدید می‌سازد.

## قواعد پردازش

- اگر مقدار `properties.name` وجود نداشته باشد یا خالی باشد، رکورد کنار گذاشته می‌شود.
- اگر مقدار `translate.name` موجود باشد، رکورد دوباره ترجمه نمی‌شود.
- اگر یکی از برچسب‌های ویرایش شناخته‌شده وجود داشته باشد، ترجمهٔ قبلی جایگزین می‌شود.
- نام‌های تکراری با توجه به نام، لایه و کلاس فقط یک‌بار برای مدل ارسال می‌شوند.
- ترجمه‌های دریافت‌شده در یک حافظهٔ میانی ثبت می‌شوند تا اجرای قطع‌شده ادامه‌پذیر باشد.
- فایل ورودی هیچ‌گاه در محل خودش بازنویسی نمی‌شود.

## اجرای رابط محلی

```powershell
npm.cmd install
npm.cmd run dev
```

نشانی پیش‌فرض برنامه:

```text
http://127.0.0.1:3005/
```

برای اجرای کامل از داخل رابط، دکمهٔ «پردازش فایل کامل» را بزنید و فایل پشتیبان را انتخاب کنید. رابط تعداد ردیف‌ها و نام‌های یکتا را نشان می‌دهد. ترجمه را می‌توان متوقف کرد و بعداً با انتخاب دوبارهٔ همان فایل ادامه داد. دریافت فایل نهایی فقط پس از کامل‌شدن صف فعال می‌شود.

خود فایل در مرورگر پردازش می‌شود. فقط نام مبدأ، لایه، کلاس و شناسهٔ داخلی صف برای ترجمهٔ برخط ارسال می‌شوند.

## پویش فایل بدون ترجمه

این فرمان فقط آمار صف را گزارش می‌کند و هیچ خروجی جدیدی نمی‌سازد:

```powershell
python scripts\process_sql_translations.py "C:\Users\AI\Downloads\backup_file.sql" --dry-run
```

## آزمایش تولید فایل بدون کلید مدل

حالت نمونه فقط از ترجمه‌های بازبینی‌شدهٔ موجود در پوشهٔ مثال استفاده می‌کند و برای تولید نهایی مناسب نیست:

```powershell
python scripts\process_sql_translations.py "C:\Users\AI\Downloads\backup_file.sql" `
  --provider demo `
  --limit 5 `
  --output "outputs\backup_file_demo_translated.sql" `
  --cache "outputs\demo.translation-cache.json"
```

## اجرای مترجم جمنای

کلید دسترسی را فقط در متغیر محیطی نشست جاری قرار دهید و آن را داخل فایل پروژه ننویسید:

```powershell
$env:TRANSLATION_PROVIDER="gemini"
$env:GEMINI_API_KEY="کلید دسترسی جمنای"
$env:GEMINI_TRANSLATION_MODEL="gemini-3.5-flash-lite"
```

سپس پردازش کامل را اجرا کنید:

```powershell
python scripts\process_sql_translations.py "C:\Users\AI\Downloads\backup_file.sql" `
  --provider gemini `
  --output "outputs\backup_file_translated.sql" `
  --cache "outputs\translation-cache.json"
```

برای ادامهٔ یک اجرای متوقف‌شده، همان فایل ورودی، خروجی و حافظه را دوباره به فرمان بدهید. ترجمه‌های ذخیره‌شده دوباره برای مدل ارسال نمی‌شوند.

## فایل‌های خروجی

پردازشگر سه فایل می‌سازد:

- نسخهٔ کامل جدید با پسوند `sql`
- حافظهٔ ادامه‌پذیر با پسوند `translation-cache.json`
- گزارش آماری با پسوند `report.json`

## تبدیل فایل تأییدشده به حافظه ترجمه

پس از تأیید خروجی توسط کارفرما، فایل کامل تأییدشده را به حافظه ترجمه و مجموعه ارزیابی مدل‌ها تبدیل کنید:

```powershell
python scripts\build_approved_translation_assets.py "D:\path\backup_file_translated_final.sql" `
  --output "work\approved-translations" `
  --approved-at "2026-08-29"
```

این اجرا سه فایل محلی می‌سازد:

- `manifest.json` شامل اثر انگشت فایل و آمار صحت
- `translation-memory.json` شامل ترجمه‌های یکتای مورد تأیید
- سرویس زنده پیش از فراخوانی مدل، همین حافظه را با ترکیب نام، لایه و کلاس بررسی می‌کند. منبع هر نتیجه نیز جداگانه با مقدار `approved-memory` یا نام مدل ثبت می‌شود.
- اگر نام تأییدشده با یک نام یکتای بستهٔ آفلاین اوپن‌استریت‌مپ منطبق باشد، سرویس آن را به شناسهٔ ویکی‌داده مقید می‌کند. درخواست دارای شناسه فقط از همین مدخل هویت‌محور پاسخ می‌گیرد و شباهت متنی به‌تنهایی مجوز استفاده از ترجمهٔ قبلی نیست. منبع چنین نتیجه‌ای `approved-identity-memory` است.
- اندازهٔ دستهٔ مدل محلی با `LOCAL_TRANSLATION_BATCH_SIZE` کنترل می‌شود. مقدار امن اولیه `1` است و فقط پس از آزمون ظرفیت سرور افزایش داده می‌شود.
- نام کشورها، پایتخت‌های جهان و شهرهای نمونه پیش از مدل با حافظهٔ نام‌های جغرافیایی معیار بررسی می‌شوند. این حافظه از نام‌های رسمی چندزبانه به برون‌نام فارسی می‌رسد؛ برای نمونه `Deutschland` به «آلمان» و `Beijing` یا `Peking` به «پکن» تبدیل می‌شوند.
- نام‌های ترکیبیِ کنترل‌شده نیز بدون فراخوانی مدل ساخته می‌شوند. برای نمونه `Tokyo Station` و `東京駅` هر دو به «ایستگاه توکیو» می‌رسند و `Beijing International Airport` به «فرودگاه بین‌المللی پکن» تبدیل می‌شود. این قاعده فقط وقتی اجرا می‌شود که بخش نام خاص در حافظهٔ معیار وجود داشته باشد.
- تقسیمات سطح اول کشورها و عوارض طبیعیِ مناسب نقشه از نسخهٔ سنجاق‌شدهٔ داده‌های نچرال ارث وارد می‌شوند. این بخش استان‌ها، ایالت‌ها، رودها، دریاچه‌ها، دریاها، خلیج‌ها، تنگه‌ها، جزیره‌ها، کوه‌ها و رشته‌کوه‌ها را پوشش می‌دهد. نام فارسی و نام‌های چندزبانه همراه داده ذخیره می‌شوند و ساخت دوباره از کش محلی نیز ممکن است.
- بافت عارضه برای رفع ابهام استفاده می‌شود. برای نمونه `Georgia` در کلاس کشور «گرجستان» و در کلاس ایالت «جورجیا» است. نام‌های طبیعی مانند `Nile`، `Alpen` و `Lake Baikal` نیز به‌ترتیب «رود نیل»، «رشته‌کوه آلپ» و «دریاچه بایکال» برگردانده می‌شوند.
- `evaluation-set.json` برای مقایسه جمنای و مدل‌های آفلاین

اگر حتی یک رکورد نام‌دار بدون ترجمه یا یک ترجمه متعارض پیدا شود، خروجی مرجع ساخته نمی‌شود. پوشه `work` در مخزن ثبت نمی‌شود و داده کارفرما روی همان دستگاه باقی می‌ماند.

## پایگاه داده آزمایشی محلی

نسخه آزمایشی پایگاه داده از تصویر رسمی جامعه `PostGIS` و نسخه ۱۸ پایگاه داده استفاده می‌کند. ابتدا گذرواژه محلی را در نشست جاری تنظیم کنید:

```powershell
$env:POSTGRES_PASSWORD="یک-گذرواژه-محلی"
```

پس از قراردادن فایل کامل تأییدشده روی دستگاه، بازیابی کنترل‌شده را اجرا کنید:

```powershell
pwsh -File scripts\restore_approved_database.ps1 `
  -InputFile "D:\path\backup_file_translated_final.sql"
```

این ابزار در صورت وجود قبلی جدول `public.geoms` متوقف می‌شود و چیزی را بازنویسی نمی‌کند. پایگاه داده فقط روی نشانی محلی و درگاه `5434` در دسترس قرار می‌گیرد.

## سرویس محلی دادهٔ زنده

سرویس پشتیبان، جدول `public.geoms` را مستقیم از پایگاه‌داده می‌خواند، هندسه‌ها را از دستگاه مختصات `3857` به `4326` تبدیل می‌کند و مجموعه عارضه‌ها را در رابط زیر برمی‌گرداند:

```text
http://127.0.0.1:3006/api/v1/features
```

## اجرای کامل با مدل آفلاین

مدل فعال نسخهٔ نامزد تحویل، `qwen/qwen3.5-9b` است که از راه `LM Studio` و رابط محلی سازگار با `OpenAI` فراخوانی می‌شود. مدل `qwen3.5-4b` داور نخست نام‌های خاص است و مدل ۹ میلیاردی داوری دوم را انجام می‌دهد. خروجی مدل فقط پیش‌نویس است و در اجرای زمان‌بندی‌شده ثبت خودکار نمی‌شود.

مدل `google/madlad400-3b-mt` به‌عنوان مسیر تخصصی آزمایشی حفظ شده است. آماده‌سازی این مسیر اختیاری با فرمان زیر انجام می‌شود:

```powershell
pwsh -File scripts\setup_madlad_service.ps1
```

مدل و محیط پایتون در پوشهٔ محلی `work` قرار می‌گیرند و وارد مخزن نمی‌شوند. راه‌انداز زیر فقط برای مسیر اختیاری `MADLAD-400` است:

```powershell
pwsh -File scripts\start_offline_stack.ps1
```

ترتیب پیش‌فرض تصمیم‌گیری به این صورت است: ترجمهٔ تأییدشدهٔ کارفرما، نام معیار جغرافیایی، قواعد کنترل‌شده و سپس مدل محلی. درخواست دارای شناسه فقط از مدخل هویت‌مند حافظهٔ کارفرما استفاده می‌کند؛ بنابراین ترجمهٔ مشابه متعلق به عارضه‌ای دیگر وارد نتیجه نمی‌شود. نام‌های تأییدشده و قواعد قطعی بدون بازبینی انسانی ثبت‌پذیرند. رأی دو مدل دربارهٔ نام خاص تازه فقط برای اولویت‌بندی صف استفاده می‌شود و به‌تنهایی مجوز ثبت خودکار نیست؛ زیرا توافق مدل‌ها تضمین‌کنندهٔ صحت نام جغرافیایی نیست.

داشبورد، ترجمهٔ تکی، ترجمهٔ فایل کامل و ابزار خط فرمان از رابط مرکزی و خواندنی زیر استفاده می‌کنند:

```text
POST http://127.0.0.1:3006/api/v1/translation-previews
```

هر نام می‌تواند همراه شناسهٔ اختیاری `wikidataId` و مختصات `longitude` و `latitude` فرستاده شود. شناسه، هویت قطعی مکان را مشخص می‌کند. در نبود شناسه، مختصات فقط برای تفکیک نام‌های جغرافیایی مبهم استفاده می‌شود. نزدیک‌ترین نامزد باید حداکثر ۱۰۰ کیلومتر فاصله داشته باشد و دست‌کم ۲۵ کیلومتر از نامزد بعدی نزدیک‌تر باشد. اگر انتخاب مطمئن نباشد، نام به مدل یا صف بازبینی می‌رود و واژه‌نامه چیزی را حدس نمی‌زند.

در نصب اولیه، `TRANSLATION_AUTO_APPLY=false` است. پس از موفقیت آزمون پذیرش، این مقدار روی `true` قرار می‌گیرد. حتی در این حالت فقط نتیجه‌های قطعی و واژه‌نامه‌ای ثبت می‌شوند و مدل آفلاین اجازهٔ ثبت خودکار ندارد.

ابزار خط فرمان نیز به‌صورت پیش‌فرض از همین مدل محلی استفاده می‌کند:

```powershell
python scripts\process_sql_translations.py "D:\path\backup_file.sql" `
  --provider local `
  --output "D:\path\backup_file_translated.sql"
```

### مدیریت اتصال از داشبورد

دکمهٔ «اتصال به پایگاه داده» در داشبورد، اتصال فعال را بدون نمایش گذرواژه نشان می‌دهد. آزمون اتصال فقط این موارد را می‌خواند و هیچ رکوردی را تغییر نمی‌دهد:

- دسترسی شبکه و ورود
- وجود افزونهٔ مکانی و جدول انتخابی
- وجود ستون‌های لازم
- مجوز خواندن، ثبت ترجمه و نگهداری تاریخچه
- آمار رکوردهای نام‌دار، در انتظار و دارای علامت ویرایش

پس از موفقیت همهٔ کنترل‌ها، مدیر می‌تواند اتصال را فعال کند. در حالت ماندگار، تنظیم اتصال در فضای محافظت‌شدهٔ سرویس پشتیبان ذخیره و پس از راه‌اندازی دوباره بازیابی می‌شود. این اطلاعات از رابط‌های وضعیت برگردانده نمی‌شوند. رابط‌های مربوط عبارت‌اند از:

```text
GET  /api/v1/database-connection
POST /api/v1/database-connections/test
POST /api/v1/database-connections/activate
```

تعویض اتصال هنگام اجرای فعال پردازشگر پذیرفته نمی‌شود. فعال‌سازی فقط برای جدولی مجاز است که همهٔ کنترل‌های خواندن، نوشتن و تاریخچه را گذرانده باشد.

پس از آماده‌بودن کانتینر، سرویس و رابط کاربری را در دو پنجره جدا اجرا کنید:

```powershell
npm.cmd run backend:start
```

```powershell
npm.cmd run dev
```

برای وارسی سریع اتصال پایگاه‌داده می‌توان رابط سلامت را خواند:

```powershell
Invoke-RestMethod http://127.0.0.1:3006/health
```

نقشه ابتدا رابط زنده را می‌خواند. اگر سرویس محلی در دسترس نباشد، فایل ثابت قبلی را بارگذاری می‌کند و این وضعیت را صریح در پیام بالای صفحه نشان می‌دهد. نشانی سرویس و مبدأهای مجاز از متغیرهای `FEATURE_API_*` و `VITE_FEATURES_API_URL` قابل تنظیم‌اند.

ترجمهٔ دستی یا خروجی مدل ابتدا فقط به‌صورت پیش‌نویس در مرورگر ذخیره می‌شود. در حالت اتصال زنده، دکمهٔ «ثبت ترجمهٔ بازبینی‌شده در پایگاه‌داده» همان رکورد انتخاب‌شده را پس از تأیید کاربر به‌روزرسانی می‌کند. این درخواست فقط `translate.name`، ارائه‌دهنده، زمان ثبت و برچسب‌های بازترجمه را تغییر می‌دهد. نام مبدأ، هندسه و سایر داده‌ها حفظ می‌شوند. اگر ترجمه از زمان خواندن صفحه در پایگاه‌داده تغییر کرده باشد، ثبت با پاسخ تعارض متوقف می‌شود.

رابط ثبت کنترل‌شده:

```text
PATCH http://127.0.0.1:3006/api/v1/translations
```

## پویشگر مداوم ترجمه

سرویس پشتیبان می‌تواند جدول را مستقیماً پویش کند. رکورد فاقد `properties.name` وارد صف نمی‌شود، ترجمهٔ موجود حفظ می‌شود و فقط نام جدید یا رکورد دارای یکی از برچسب‌های ویرایش پردازش می‌شود. نتیجهٔ اجرای آزمایشی در رابط کاربری به‌صورت پیش‌نویس نمایش داده می‌شود و پایگاه‌داده را تغییر نمی‌دهد.

```text
GET http://127.0.0.1:3006/api/v1/translation-queue
POST http://127.0.0.1:3006/api/v1/translation-jobs/run
GET http://127.0.0.1:3006/api/v1/translation-worker
```

ممیزی نام‌های جغرافیایی، داده‌های واقعی پایگاه را فقط می‌خواند و ترجمه‌های موجود را با نام معیار مقایسه می‌کند. اختلاف معنایی، تفاوت صرفاً نوشتاری و موارد حل‌نشده جدا گزارش می‌شوند. این مسیر هیچ تغییری در پایگاه داده ایجاد نمی‌کند و نتیجه‌ای را نیز خودکار تأیید نمی‌کند.

```text
GET http://127.0.0.1:3006/api/v1/geographic-identity-audit
GET http://127.0.0.1:3006/api/v1/osm-identity-enrichment
```

رابط دوم، شناسه‌های نوع و شمارهٔ عارضه را با یک بستهٔ محلی برگرفته از اوپن‌استریت‌مپ تطبیق می‌دهد. این بسته برای اجرای آفلاین همراه سرویس نگهداری می‌شود. نتیجه فقط پیشنهاد هویت است؛ نه شناسه و نه ترجمه را در پایگاه ثبت نمی‌کند. دریافت انبوه از رابط اصلی اوپن‌استریت‌مپ نیز بخشی از اجرای مداوم سامانه نیست.

برای نوسازی بسته در زمان آماده‌سازی یا پس از دریافت پایگاه تازهٔ کارفرما، دستور زیر عوارض جغرافیایی نام‌دار را فقط‌خواندنی بررسی می‌کند و نام، نسخه و شناسهٔ ویکی‌دادهٔ متناظر را در یک فایل محلی می‌گذارد:

```powershell
node --env-file-if-exists=.env --env-file-if-exists=.env.local scripts\build_osm_identity_snapshot.mjs
```

سرویس در اجرای بعدی فایل `work/identity/osm-identity-snapshot.json` را بارگیری می‌کند. همین نمونهٔ بارگیری‌شده به پویشگر، حافظهٔ ترجمهٔ تأییدشده و مسیر ترجمهٔ تکی داده می‌شود تا همهٔ مسیرها از یک هویت استفاده کنند. تطبیق اولیه فقط وقتی پذیرفته می‌شود که نوع عارضه، شمارهٔ عارضه و نام مبدأ همگی برابر باشند؛ بنابراین تغییر نام یا جابه‌جایی شناسه باعث عبور مورد به مسیر کنترل‌شده می‌شود. پس از احراز شناسه، حافظهٔ تأییدشده می‌تواند ترجمهٔ همان عارضه را حتی با نام مبدأ تازه بازیابی کند.

هنگام نوسازی، نام قبلی فقط در صورتی به‌عنوان سابقه نگهداری می‌شود که نوع عارضه، شمارهٔ عارضه و شناسهٔ ویکی‌داده همگی ثابت مانده باشند. اگر شناسهٔ ویکی‌داده تغییر کند، سابقه کنار گذاشته می‌شود تا ترجمهٔ عارضه‌ای دیگر به اشتباه استفاده نشود.

آزمون پذیرش چرخهٔ نام تازه، برچسب ویرایش و تغییر نام هویت‌مند فقط روی پایگاهی اجرا می‌شود که نام آن شامل `_acceptance_` باشد:

```powershell
node --env-file-if-exists=.env --env-file-if-exists=.env.local scripts\run_identity_cycle_acceptance.mjs
```

پویشگر ترجمه پیش از ساخت کلید نام و فراخوانی مترجم، همین بستهٔ محلی را بررسی می‌کند. اگر نوع عارضه، شمارهٔ عارضه و نام مبدأ همگی منطبق باشند، شناسهٔ ویکی‌داده فقط در حافظه به ورودی ترجمه افزوده می‌شود. این شناسه در فایل یا پایگاه کارفرما نوشته نمی‌شود. در نتیجه، نام‌های جغرافیایی قطعی مستقیماً از فرهنگ‌نامه پاسخ می‌گیرند و نام‌های مبهم همچنان بسته می‌مانند.

پس از تأیید خروجی کارفرما، اجرای مداوم با این تنظیمات فعال است:

```dotenv
TRANSLATION_WORKER_ENABLED=true
TRANSLATION_AUTO_APPLY=true
TRANSLATION_ALLOW_API_APPLY=false
```

پویشگر در شروع سرویس یک‌بار فوری بررسی می‌کند و سپس هر پنج دقیقه تکرار می‌شود. ثبت خودکار فقط برای حافظهٔ تأییدشدهٔ کارفرما، هویت تأییدشده، نام‌های جغرافیایی معیار، واژه‌های عمومی کنترل‌شده و شناسه‌های حفظ‌شده مجاز است. این مسیر مدل را فراخوانی نمی‌کند؛ نام‌های ناشناخته در صف باقی می‌مانند. گزینهٔ سوم خاموش است؛ بنابراین فراخوانی دستی نمی‌تواند بدون مجوز ثبت نهایی انجام دهد. هر ثبت خودکار در تاریخچه ذخیره می‌شود و سازوکار بازگردانی امن در دسترس می‌ماند.

درگاه مدل از جمنای، اوپن‌ای‌آی و سرویس محلی سازگار با رابط اوپن‌ای‌آی پشتیبانی می‌کند. برای استفاده از `LM Studio` یا `Ollama`، ارائه‌دهنده را روی `local` بگذارید و نشانی و نام مدل محلی را در متغیرهای `LOCAL_TRANSLATION_*` تنظیم کنید. رابط کاربری و منطق صف با تغییر مدل عوض نمی‌شوند.

## مقایسهٔ مدل‌ها

دکمهٔ «مقایسهٔ جمنای و مدل محلی» در جزئیات هر عارضه، همان نام و بافت لایه را به هر دو مدل می‌فرستد. نتیجه‌ها، زمان پاسخ و وضعیت آمادگی جداگانه نشان داده می‌شوند. این آزمون فقط‌خواندنی است. نتیجه تنها در صورت انتخاب کاربر به پیش‌نویس مرورگر می‌رود و باز هم بدون تأیید جداگانه در پایگاه داده ثبت نمی‌شود.

```text
GET http://127.0.0.1:3006/api/v1/translation-providers

GET http://127.0.0.1:3006/api/v1/translation-memory

GET http://127.0.0.1:3006/api/v1/canonical-place-names
POST http://127.0.0.1:3006/api/v1/translation-comparisons
```

برای سرویس داکری، نشانی ال‌ام‌استودیو به‌صورت پیش‌فرض از میزبان ویندوز خوانده می‌شود:

```dotenv
LOCAL_TRANSLATION_BASE_URL_DOCKER=http://host.docker.internal:1234/api/v1
LOCAL_TRANSLATION_MODEL=qwen/qwen3.5-9b
LOCAL_TRANSLATION_API_KEY=lm-studio
PROPER_NAME_JUDGE_MODEL=qwen3.5-4b
PROPER_NAME_JUDGE_SECONDARY_MODEL=qwen/qwen3.5-9b
```

برای اولاما فقط درگاه به `11434` تغییر می‌کند. نام مدل باید دقیقاً با خروجی فهرست مدل‌ها یکی باشد.

در نسخهٔ نامزد تحویل، مدل `qwen/qwen3.5-9b` مترجم و داور دوم است و مدل `qwen3.5-4b` داوری نخست را انجام می‌دهد. مقدار نمونهٔ `TRANSLATION_AUTO_APPLY=false` برای نصب امن نگه داشته شده است؛ پس از آزمون پذیرش، راهنمای استقرار فعال‌سازی محدود آن را توضیح می‌دهد.

## تاریخچه و بازگردانی

سرویس هنگام شروع، فضای مستقل `translation_service` و جدول `translation_audit` را در صورت نبودن ایجاد می‌کند. ساختار جدول اصلی `public.geoms` تغییر نمی‌کند. هر ثبت ترجمه و رویداد تاریخچه در یک تراکنش انجام می‌شوند و این اطلاعات را نگه می‌دارند: نام مبدأ، ترجمهٔ قبلی، ترجمهٔ جدید، مدل یا ارائه‌دهنده، علت و زمان ثبت.

```text
GET http://127.0.0.1:3006/api/v1/translation-history
POST http://127.0.0.1:3006/api/v1/translation-history/{id}/rollback
```

بازگردانی فقط زمانی انجام می‌شود که نام مبدأ و ترجمهٔ جاری با همان رویداد تاریخچه منطبق باشند. در صورت وجود تغییر جدیدتر، پاسخ تعارض برگردانده می‌شود و داده بازنویسی نخواهد شد. خود بازگردانی نیز یک رویداد تازه در تاریخچه ثبت می‌کند.
